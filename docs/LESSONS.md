# LESSONS — verified facts, append-only

Every entry here was **measured**, not assumed, and most of them cost a debugging
session to find. They are recorded so the next agent does not rediscover them.

This file is deliberately not in `PROGRESS.md`. That is a status board with a
120-line cap where a closed phase collapses to one row; this is an append-only log
that never collapses. An entry leaves only when the thing it describes stops being
true — not when it stops being recent.

- **2026-09-02** **A transiently empty page in the middle of a run erased its items permanently**, and a fully green suite did not see it. The watermark is a high-water mark on `published_at`: promoting it after skipping a page puts everything that was on that page below it, so `alreadySeen()` rejects those items on every later run — not retried, gone. Proven with `tests/Feature/Ingestion/EmptyMiddlePageTest.php` (three pages, middle one blank on run 1: `middle` never arrived even on a healthy run 2), then fixed. Promotion moved out of the connectors and into `IngestionRunner`, which is the only party that sees the whole run, and is gated on `! $page->hasMore && ! $sawEmptyPage`. **`$capped` alone is the wrong test**: the App Store connector reports `hasMore=false` exactly as it reaches the platform's depth limit of 10, tripping the runner's cap in the same iteration, and that run *is* complete — what must block promotion is the runner cutting a run short while the connector still had more. Found by review, not by the suite; the existing tests only covered an empty *first* page, which is the recoverable case.
- **2026-09-02** `Broadcast::channel()` registers on the broadcaster instance of whatever connection was **default at boot** — it reaches the driver through `BroadcastManager::__call`, and channels live on the broadcaster, not the manager. A test that switches `broadcasting.default` afterwards gets a fresh broadcaster with no channels, so every authorization answers **403** — including the ones that should succeed, which silently makes the negative tests pass for the wrong reason. Re-`require` `routes/channels.php` after the switch.
- **2026-09-02** **Route-model binding runs before any middleware that is not in `$middlewarePriority`.** `SubstituteBindings` is in that list, `SetTenantContext` was not, so binding queried the model with no tenant and `CompanyScope` threw: `GET /api/v1/feedbacks/{feedback}` answered **500 instead of the 404** invariant I1 requires. Same sorting rule as the `SetLocale`/`Authenticate` finding above.
- **2026-09-02** The compose stack mounted only `../backend` into the backend container, so `contracts/` did not exist there and every invariant **I7** contract test **skipped** — the one outcome a contract test must not have. Fixed with `- ../contracts:/srv/contracts:ro`.
- **2026-09-02** `pcntl_fork` + `DB::purge()` in the child **kills the parent's connection**: purge destructs the inherited PDO, whose destructor writes a termination packet down the socket the parent is still using, and the parent dies with "server closed the connection unexpectedly" while rolling back `RefreshDatabase`'s transaction. The child must never touch the inherited handles — point it at a connection name that has never been opened in the process tree, and end on SIGKILL so nothing destructs.
- **2026-09-02** `CarbonImmutable::toDateTimeString()` **drops the offset**. App Store's `2026-08-27T23:40:59-07:00` therefore reached the `timestamptz` column as `23:40:59` UTC — the right wall clock in the wrong zone, **seven hours off the actual instant**, and it would have skewed every trend chart built on `published_at`. Use `toIso8601String()`.

- **2026-09-02** ADR-0007's ratchet clause was **unsatisfiable from the day it was written**. It required floor >= 90% of the threshold, but a threshold derived as `floor + allowance` gives `floor / threshold = 1 - allowance / threshold`, which is 75% at 80/320; the ratio at the time was 245.00/320 = **76.6%**. The rule rejected its own thresholds. Replaced (ADR-0008) with an attribution-based classification: a raise needs the per-source table to show the `src/` line did not grow.
- **2026-09-02** **Test database isolation never worked, and the test meant to prove it passed anyway.** Two layers. First, compose injects `backend/.env` via `env_file:`, so `DB_DATABASE=omnihear` existed as a real environment variable and PHPUnit's `<env force="true">` could not beat it (Laravel's `Env` reader consults `$_SERVER`/`$_ENV` before the `putenv()` layer PHPUnit writes). `RefreshDatabase` ran `migrate:fresh` against the **development** database once (schema only, no rows). `tests/bootstrap.php` closed that by writing all three layers before the autoloader. Second — the part that hid for two waves — `phpunit.xml` *also* declared `DB_DATABASE`, and PHPUnit applies `<env force="true">` **after** the bootstrap runs, so the bootstrap's choice was overwritten every time and its `test_tmp_` branch was dead code. **Six agents across two waves each believed they had a private database and were all writing to `omnihear_test` at once.** Proven: `test_tmp_f2h` finished a full wave with **zero tables** while `omnihear_test` had 17. Fixed by deleting the line from `phpunit.xml`, leaving `tests/bootstrap.php` the single authority; verified with `-e DB_DATABASE=test_tmp_f4`, which took that database from 0 to 17 tables. `DatabaseIsolationTest` now asserts the connected database **equals the one requested** — asserting only the *shape* of the name is what let it pass through all of this. `guard-test-db-target` was taught that the bootstrap is the authority, since it had been checking `phpunit.xml` for the very line that had to go.

- **2026-09-03** **A coverage run can die after reporting success.** `php artisan test --coverage --min=80` crossed the image's 128M `memory_limit` once the suite passed ~950 tests: php-code-coverage serializes the whole coverage object at the end, and it died in `Report/PHP.php` **after** `Tests: … passed` had already been printed — so the run looked green and the gate's coverage number silently never appeared. `-d memory_limit` on artisan does not help: `php artisan test` spawns the Pest process and the flag is not inherited. - **2026-09-03** **`php artisan serve` filters the environment, so compose's `environment:` block never reached the running application.** With a `.env` present, `serve` starts the `php -S` child with everything except its own passthrough list blanked out, so an edited `.env` is picked up on the next request. In a container the effect is that only `backend/.env` reaches the process answering HTTP — the compose overrides reach the CLI and nothing else. The comment this file previously carried, that `compose environment overrides env_file so backend/.env cannot drift out of sync`, was **true for CLI and false for the running app**; `AI_SERVICE_HMAC_SECRET` only worked because `backend/.env` happened to hold the right value. Found by evidence, not inspection: `Mail::raw` through `artisan tinker` reached Mailpit while `POST /auth/email/resend` in the same container wrote to `storage/logs`, because `MAIL_MAILER` had fallen back to the config default. Fixed by adding `--no-reload` to the compose command, which passes the environment through unfiltered.
- **2026-09-03** **Analysis never ran in the dev stack.** `AnalyzeFeedbackJob` dispatches to `config('ai.queue')`, default `analysis`, but `backend/config/horizon.php` does not exist, so Horizon runs on the package default and watches `['default']` only. Measured: ingestion finished, five payloads sat in `omnihear_database_queues:analysis` (`LLEN` 5), `default` was empty, and `analyzed_feedback_count` stayed 0. Pest cannot see this — the queue is `sync` there. A stopgap `AI_ANALYSIS_QUEUE: default` sits in compose, marked as such; the real fix is publishing `config/horizon.php` with a supervisor watching both queues.
- **2026-09-03** **`$middlewarePriority`, fourth time.** `throttle:api` sat inside the authenticated stack, but `Authenticate` precedes `ThrottleRequests` in the priority list, so an invalid or absent token 401'd *before* the throttle ran — every `/api/v1/*` route was unlimited for unauthenticated callers, each request still costing a token lookup. It also made `AppServiceProvider`'s `?? $request->ip()` fallback unreachable code that reads like protection. Adding a second `throttle:` to the front does not help: both are the same class and priority sorting moves both behind `Authenticate`. The shape that works is a middleware **absent** from the priority list, prepended to the `api` group the way `CorrelationId` is.
- **2026-09-03** **A whole authorization boundary can be invisible to a suite that never sends a real token.** Sanctum abilities were enforced nowhere — no route checked one — and `config/sanctum.php` was unpublished, so tokens never expired. Every test in `ApiKeyTest` used `actingAs($user, 'sanctum')`, which installs a `TransientToken`, so no test ever put a real bearer token on the wire: deleting ability enforcement entirely would have turned nothing red. When a test exercises an auth boundary, it has to travel the path production travels.
- **2026-09-03** **Sanctum's own `abilities:` middleware cannot express "this is not an API key".** It resolves through `can()`, and a legacy `['*']` token answers true to everything — so using it would have promoted every pre-split token to an API key, the exact opposite of what `TokenAbility::isSession()` decided. A boundary that treats a wildcard as *less* privileged needs its own check.
- **2026-09-03** **A container reads `env_file` once, at creation.** `docker compose restart` does not re-read it; `up -d --force-recreate` does. An `APP_KEY` added to `backend/.env` during a debugging session looked ignored until the container was recreated.
- **2026-09-03** **Realtime was broadcasting into a TLS connection to itself.** `backend/.env.example` ships `REVERB_HOST=localhost` and no `REVERB_SCHEME`, and Laravel defaults the scheme to `https` — so the server-to-server publish (horizon → Reverb's REST API) went to `https://localhost:8080`, which inside a container is that container, over TLS nothing there speaks. The failure was **silent**: a real websocket client subscribed successfully (`pusher_internal:subscription_succeeded`) and simply never received an event. Fixed with `REVERB_HOST: reverb` and `REVERB_SCHEME: http` on `backend` and `horizon` in compose. Same shape as the HMAC drift of 2026-09-02 — two services green in isolation, the path between them broken.
- **2026-09-03** **The E2E job had never run from a clean checkout, and its green was borrowed from the developer's machine.** The first CI run after W7 died in `Wait for the stack` with `reverb-1 | require(/srv/backend/vendor/autoload.php): Failed to open stream: No such file or directory` — the compose stack bind-mounts `../backend`, so `vendor/` comes from the checkout, and nothing in the job installed it. Two more of the same class were behind it: `APP_KEY` ships empty in `.env.example`, and the postgres volume is new on every runner so there is no schema. All three are the one-time local setup a developer does once and stops seeing; the suite passed for the agent that wrote it because that machine had had all three since F2. This is precisely the gap CLAUDE.md §2 names — *CI runs on a clean checkout, the local gate runs in a working tree* — and it is not limited to untracked files: a gitignored build artifact produces it just as well. Fixed with a `Prepare the backend (vendor, key, schema)` step running `composer install`, `key:generate --force` and `migrate --force` through `docker compose run` before the stack starts. The other six jobs were green on the same run.
- **2026-09-03** **`Http::fake()` merges stub callbacks; it does not replace them.** A second `Http::fake(closure)` inside a test that already installed one leaves the first closure in charge, so the second phase of a two-phase test never runs — and the test stays green while proving nothing. It cost both W8 connector tracks a debugging pass and, in each, one test that looked like an invariant I5 proof was asserting against a response the happy path never produced. The shape that works is a single closure driven by a mutable script, with the request count asserted so the later phase is visibly reached. Same family as the `Broadcast::channel()` finding: a test can pass for the wrong reason and read as evidence.
- **2026-09-04** **A query with no `ORDER BY` compared with an order-sensitive assertion passes alone and fails in the suite.** `Feedback::query()->pluck('external_id')->all()` matched with Pest's `toBe()` in `GooglePlayIngestionTest` returned the right two ids in the other order once the full suite had populated the heap ahead of it — the same test passed **three times out of three** run on its own. PostgreSQL guarantees no row order without `ORDER BY`, so the assertion had never been sound; it had been lucky since W8 and the luck ran out in W9's gate. Eleven call sites across the seven `tests/Feature/Ingestion/` files were audited: nine were already safe (both sides sorted, or the assertion is `toHaveCount`/`unique()`/a `foreach` that never reads the order), two were not. The fix is to sort the stored side — both `gpiIngestableIds()` and `zdIngestableIds()` already `sort()` before returning — **not** to add an `orderBy` that invents a sequence the test does not mean. Where a test does mean a sequence, the order has to be made explicit rather than relaxed. Same family as the `Http::fake()` and `Broadcast::channel()` findings: green for a reason it never stated.
- **2026-09-04** **`config/horizon.php` is published and the analysis queue drains — the 2026-09-03 entry above is closed.** Measured on the compose stack: `LLEN omnihear_database_queues:analysis` went **5 → 0** within ~6-9 s of `up -d --force-recreate backend horizon`, `analyzed_feedback_count` summed to 73, and no analysis job reached `failed_jobs`. `restart` is not enough — a container reads `env_file` at creation, so a restarted container keeps the old `AI_ANALYSIS_QUEUE` and the measurement goes green for the wrong reason. **The trap inside the fix:** `ProvisioningPlan::deploy()` (`vendor/laravel/horizon/src/ProvisioningPlan.php:105-111`) resolves the environment with `collect()->first(fn ($_, $name) => Str::is($name, $environment))` and then `if (empty($supervisors)) { return; }` — so a config whose `environments` array has no key matching `APP_ENV` deploys **zero supervisors while Horizon still reports itself as running**. The published config must carry a key matching the environment compose actually runs (`local`, from `backend/.env`), and the test must assert the match with `Str::is`, the way production resolves it, not with `array_key_exists`. A `'*'` catch-all was tried and removed: it hides a typo'd `APP_ENV` instead of surfacing it, and it makes the coverage test pass even if the named block it exists to pin is deleted.
- **2026-09-04** **`ext-imap` still compiles on `php:8.3-cli-alpine`; that is not why it was rejected.** Measured, so the next agent does not re-measure it: Alpine 3.24 ships `imap-dev 2007f-r16`, `apk add imap-dev krb5-dev openssl-dev` then `docker-php-ext-configure imap --with-kerberos --with-imap-ssl` and `docker-php-ext-install imap` all succeed, and `php -m` lists `imap`. It was rejected because the C library underneath it, UW c-client, was last released in **2007**; PHP 8.4 unbundled the extension by an RFC that passed **27-0**, and it cannot authenticate against providers that require XOAUTH2. The same reasoning ADR-0003 applied to Laravel 11's EOL applies here: soldering a dead dependency into the image is taking the same decision again in two years. The email connector is therefore deferred, to be built either against an HTTP provider API (Gmail/Graph — which fits the W8 recipe, `Http::fake()` and the `GooglePlayAccessToken` pattern, and needs only a three-legged OAuth flow the tree does not have yet) or with a maintained MIME parser plus a hand-written IMAP client in its own wave. `webklex/php-imap` was the only pure-PHP candidate covering both halves and its last commit is 2025-05-07 with 122 open issues.
